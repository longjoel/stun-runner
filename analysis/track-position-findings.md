# Track timing and progression state

This note separates the value that appears to advance continuously during a
race from the state/index word that selects a ROM table at a course transition.
The distinction matters: a course selector is not automatically a geometric
position, and a monotonically changing word is not automatically a timer.

## Current evidence

The strongest timing source is `0xFFFF8014` in 68010-visible RAM. The static
listing shows it being used as a continuously available source for road and
object calculations:

| PC | Literal operation | Interpretation status |
|---|---|---|
| `0x0222DE` | `addq.l #1,$8014.w` in the interrupt handler, which is the sign-extended 68010 address `0xFFFF8014` | interrupt-driven global tick; runtime writer confirmed |
| `0x02C0F4` | copy `0xFFFF8014` to `0xFFDCC0` | source-to-trajectory mirror; observed mechanism |
| `0x035CB0` | subtract `0xFFDCC0` from `0xFFFF8014`, compare with `0x78`, and refresh the mirror | bounded movement/progress delta check; semantics not named |
| `0x02F246` | copy `0xFFFF8014` to `0xFFDB36` immediately around the road FIFO submission path | road-consumer timing/progress landmark |
| `0x036998`, `0x03734A`, `0x038034` | shift `0xFFFF8014` left by eight before object/geometry helpers | position-derived placement input |
| `0x03DF9C`, `0x03E0AC`, `0x03E1D6` | copy it to `0xFFDDEC`, then derive `0xFFDDF0 = source + 0x3A98` | object-event interval/placement input |
| `0x03B382` | mask a shifted form of the source into a movement value | position-derived motion input |

These are literal data-flow observations from the main-CPU listing. The
writer trace below changes the interpretation: the source is a global
interrupt tick. The downstream consumers may derive elapsed time, placement,
or progress from it, but `0xFFFF8014` itself is not proven to be distance along
the current table.

## Snapshot correlation

The recorded race snapshot series (`/tmp/race`, frames 1200–4800) has these
big-endian 32-bit values at `0xFFDCC0`, the mirror established above:

| Frame | `0xFF9578` state/index | `0xFFDCC0` mirror | `0xFF9564` elapsed candidate |
|---:|---:|---:|---:|
| 1200 | 5 | 4,353 (`0x1101`) | 142 |
| 1800 | 5 | 6,733 (`0x1A4D`) | 332 |
| 2400 | 5 | 9,164 (`0x23CC`) | 519 |
| 3000 | 5 | 11,565 (`0x2D2D`) | 686 |
| 3600 | 5 | 14,054 (`0x36E6`) | 852 |
| 4200 | 5 | 16,439 (`0x4037`) | 1,032 |
| 4800 | 5 | 18,923 (`0x49EB`) | 1,212 |

The mirror increases throughout this settled race interval while the course
state remains unchanged. This distinguishes it from `0xFF9578`, which is a
state/index word used by the award path and ROM table selector. The similar
monotonic behavior of `0xFF9564` is why neither value should be called a
position based on snapshots alone: `0xFF9564` is independently identified as
an elapsed-update counter by its `0x024506` increment, while `0xFFFF8014` is
the lower-level interrupt tick.

## Writer trace correction

A bounded replay of `/tmp/race/r1.inp` initially traced the literal
`0xFFFF8014` address and found no events because the installed MAME address
space is 24-bit. Repeating the same trace at bus-visible `0xFF8014–0xFF8017`
captured 34,064 events, untruncated, with one writer:

| Writer PC | Frames | Addresses | Events | Observation |
|---|---:|---|---:|---|
| `0x0222DE` | 600–4799 | `0xFF8014`, `0xFF8016` | 34,064 | four longword tick updates per frame, each represented by two 16-bit writes |

The first low-word values at frame 600 were `1937..1940`; values at frame
4799 were `18965..18968`. The approximately four updates per frame and the
listing's `RTE` immediately after the increment identify this as interrupt
timekeeping. This is stronger than snapshot monotonicity and supersedes the
earlier position/progress wording.

## Storage model so far

The current evidence supports this conservative model:

```text
0xFFFF8014  interrupt-driven global tick
     ├──> 0xFFDCC0 / 0xFFDCC4 trajectory mirror and update gate
     ├──> 0xFFDB36 road/FIFO progress landmark
     ├──> shifted inputs to object/geometry helpers
     └──> 0xFFDDEC / 0xFFDDF0 object-event interval state

0xFF9578    separate progression state/index
     └──> finite ROM table selector at 0x047406
```

`0xFFFF8014` is now resolved as a timing source rather than a spatial state.
The remaining high-value experiment is to trace the actual writes to the
road-progress fields fed by this tick and compare them with road-buffer
uploads and `0xFF9578` transitions. The physical track-position field remains
**UNKNOWN**.
